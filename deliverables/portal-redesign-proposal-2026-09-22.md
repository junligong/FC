# FC27 情报台 改版方案（2026-09-22）

> 基于当前 `dashboard.mjs` 模板，提出 **5 处改动**。用户确认后逐项落地。

---

## 一、现状诊断

| 问题 | 说明 |
|---|---|
| 首页信息密度低 | Hero + 报告卡 + 右侧栏三层结构，但关键数据（今日关注列表 Top 5、行情速览）需点进「FC27 市场」子标签才能看到 |
| 市场数据入口深 | 用户想快速看「今天什么卡值得注意」，需要：导航→FC27 市场→关注列表子标签→滚动 |
| 今日行情无速览 | index.html 顶栏只有一行「🔴 2026-09-22 · 北京时间」，没有今天价格口径、观测点数等核心指标 |
| 历史日报顺序固定 | archive 链接按日期倒序排列，但用户更想看到「今天最新」和「本周重点」 |
| 没有异常提示 | football/market/evolution/icons-heroes 今日都是 `partial`，但首页卡片 badge 只显示「● 当日部分完成」，不告诉你为什么 partial |

---

## 二、改版方案（5 处改动）

### 改动 1：增加「行情速览条」—— Hero 上方

**位置**：`topbar` 下方、`hero` 上方，横跨整个主区域

**内容**（实时从 `watchlist.json` 读取）：

```
📊 今日行情速览
追踪 1,231 张 | 有效价 285 张（Console 284 / PC 255） | 热度 819 张
价格口径: partial-live | 本轮 4 个观测点（003–12时）| 最近更新 12:52
```

**样式**：深灰底 `--surface-2`，左侧 lime 竖线，字体 13px， muted 色。移动端换行显示。

**实现**：`merge_daily_report.mjs` 生成 `dailyReport()` 时，读取 `automation/runs/<D>/market/watchlist.json`，提取上述字段拼成 HTML 字符串传入。

---

### 改动 2：首页右侧「今日市场速览」—— 替代现有 stat-grid

**位置**：右侧栏第一个 panel（原 evolution panel 位置），标题改为「今日市场速览」

**内容**（今日数据示例）：

```
追踪卡 1,231  有效价 285
热度 819       关注榜 285
观测点 4       异动 214

━━━━━━━━━━━━━━━━━━━━━━
🔥 关注榜 Top 5
──────────────────────
#1  安东尼·戈登  OVR83  热度68  关注分91
    理由: 热度前列 · 同档低价

#2  长谷川唯     OVR88  热度50  关注分89
    理由: 热度前列 · 同档低价

#3  芭芭拉·班达  OVR88  热度55  关注分87
    理由: 热度前列 · 同档低价

[进入关注列表 →]
```

**样式**：每张卡 3 行（排名+姓名+OVR/热度/分数），理由用 muted 色小字。底部「进入关注列表」按钮跳转到 market-watch 子标签。

**实现**：`merge_daily_report.mjs` 读取 `watchlist.json` 的 `lists.watch[:5]` 拼成 HTML，传入 `dailyReport()`。

---

### 改动 3：市场子标签增加「今日速览」Tab

**位置**：市场概览 / 市场扫描 / 关注列表 后，新增第 4 个子标签「今日速览」

**内容**：
- 今日行情速览条（同改动 1）
- 关注榜 Top 10（完整列表，非 Home 侧栏的精简版）
- 异动榜 Top 5（`|变动| ≥ 1%` 的卡）
- 同档低价榜 Top 5

**实现**：`render-market-watch.mjs` 增加一个 `--summary` 模式，或直接在 `dashboard.mjs` 里从 `watchlist.json` 读取数据拼接。

---

### 改动 4：首页报告卡增加「异常原因」展开

**位置**：每个报告卡的 badge 右侧，增加「？」图标

**交互**：点击「？」展开 tooltip，显示 `state.json` 里的 `evidence.missing` 列表（前 3 条）

**示例**（football 卡片）：
```
● 当日部分完成  ?
─────────────────
• mls_east: 射手榜/助攻榜仅存在联盟总榜
• mls_west: 射手榜/助攻榜仅存在联盟总榜
• 德甲战报类: 本轮帕德博恩3-1霍芬海姆等仅见赛果
[查看完整原因 →]
```

**实现**：`merge_daily_report.mjs` 读取各模块 `state.json` 的 `evidence.missing`，拼成 `<button class="btn sm" data-missing="...">?</button>` 插入报告卡。

---

### 改动 5：历史日报按「内容完整度」排序

**位置**：历史日报列表（`#view-archive`）

**当前**：按日期倒序（2026-09-22, 2026-09-21, ...）

**改动**：按「完整度」排序，完整度 = 当日成功模块数 / 总模块数

**示例**：
```
2026-09-22 (今天)  ★ 5/5 全部完成
2026-09-21         ★ 4/5 部分完成（football 采集失败）
2026-09-20         ★ 5/5 全部完成
...
```

**实现**：`merge_daily_report.mjs` 读取 `automation/runs/<D>/*/state.json`，计算完整度，在生成 `archiveLinks` 时附加完整度 chip。

## 四、待确认问题

1. **改动 2 的 Top 5 是否要带头像？** 当前 `watchlist.json` 不含头像数据，需要从 `current.json` 或 `player-avatar` 索引补。头像会让卡片更直观，但增加渲染复杂度。

2. **行情速览条的更新频率？** 每 4 小时随市场任务刷新，还是每次用户打开页面时 JS 动态读取 `current.json`？

3. **改动 4 的「？」按钮是否要持久化？** 点击后是 tooltip（悬停消失）还是展开面板（需手动关闭）？

4. **改动 5 的排序是否要可切换？** 提供「按日期」「按完整度」两个排序选项？
